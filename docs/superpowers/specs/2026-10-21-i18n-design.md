# OpenShell 多语言设计

日期：2026-10-21
状态：聊天方案已认可；本文待审阅。仅提交设计，不包含功能实现。

## 目标与范围

默认英文，在现有设置的外观页顶部提供 Language / 语言选择；首批支持 English（en）和简体中文（zh-CN）。未来增加语言通过新增语言包和注册语言完成。
覆盖整个应用生成的可见文案、无障碍标签、应用错误、命令和自动任务状态，以及 AI 默认回答语言。不翻译用户数据、服务器输出或既有聊天记录。

## 当前结构

前端为 React + TypeScript，设置位于 frontend/src/components/SettingsDialog.tsx，应用状态和首屏加载位于 frontend/src/App.tsx。
app.go 的 State 返回设置，SavePreference 对设置键和值做白名单校验；internal/store/sqlite.go 已提供 preferences 表，无需数据库表结构迁移。
frontend/src/bridge.ts 的 errorText 目前直接展示错误文本。
internal/ai/system.go 将助手固定为中文；app.go 调用 SystemMessage。
internal/tasks/automatic.go 的任务 reason 和 internal/domain/types.go 的执行结果 reason 目前为自然语言字符串。
因此仅替换 JSX 文案不足以实现完整多语言。

## 用户交互

- 首次启动、旧配置无 language 字段、持久化值无效时，使用 en。不自动检测系统语言。
- 语言选项始终显示 English 和简体中文，标签显示 Language / 语言，便于切回。
- 语言独立于外观页的保存按钮，选择后立即保存并切换；保存期间禁用选择，避免并发写入覆盖。
- 保存失败时保留原语言，并用原语言显示失败信息，允许重试。
- 首屏先读取 State 和初始化语言，再显示主界面；加载失败时提供英文失败提示和重试，不永久空白。
- 重启沿用成功保存的语言。不重建终端或断开 SSH，不清除标签、输入内容、命令提议或聊天记录。
- 切换时刷新菜单、弹窗和状态标签；用户已输入的内容不改写。
- document.documentElement.lang 与当前语言同步。

## 前端国际化

采用 i18next + react-i18next，语言包随安装包构建，离线可用，不增加在线翻译服务或自动语言探测插件。
新增 frontend/src/i18n/ 初始化、语言注册和 TypeScript 资源类型。
新增 frontend/src/locales/en/ 与 zh-CN/，按 common、sessions、settings、terminal、ai、errors 拆分。
默认和回退语言为 en。使用稳定语义键，例如 sessions.connect、settings.language；不使用中文原文作键。
动态文本使用完整句子和参数；数量使用复数规则，不拼接句子片段。翻译键由英文资源约束。
组件使用 useTranslation；非 React 入口通过已初始化实例翻译。
状态存储语义值、翻译键及参数，而不是提前翻译的固定字符串。历史聊天及执行记录作为历史数据保留原文。
待处理弹窗用键和参数描述默认按钮及应用生成文本，确保打开时切换语言也更新。
现有自定义会话、文件夹、API 配置和快速命令名称不迁移；新建项的应用默认名称按创建时语言生成，保存后作为用户数据保留。

## 偏好与兼容

AppState 增加 language，值限定 en 或 zh-CN；前端同步类型及需要的 Wails 生成绑定。
SavePreference 增加 language 白名单校验，复用 SQLite preferences，保持其他设置不变。
读取未设置或无效的值回退 en；保存不支持的语言返回稳定错误码。
未来新语言必须同时注册允许值、资源和显示名称；保持当前两种语言和配置兼容。
浏览器预览与桌面共享语言资源，预览默认 en，不依赖桌面 API 才能渲染。

## 错误与状态协议

对应用自行生成的可预期错误引入稳定代码、参数和可选原始详情，不通过匹配中文句子判断错误类型。
错误在 Go 内部保留因果关系和原始诊断信息，前端统一由 errorText 等入口根据代码翻译。
实施时先用小型桥接验证确认 Wails Promise rejection 的实际序列化形式。若错误对象不能结构化透传，使用带固定标记的 JSON 错误信封，通过集中适配器解码；不对每个业务 API 重写返回值。
未识别或第三方错误显示本地化概要和原始详情，保留排错信息。
自动任务 reason、命令结果 reason 增加可选 reasonCode / reasonParams，兼容保留 reason 字段。状态显示优先按代码翻译，未知代码显示原始详情。
错误文本不作为权限判定依据，执行状态、提议 ID 和权限控制逻辑保持原义。
覆盖 app、domain、store、ssh、ai、tasks 中所有会到达用户界面的应用生成提示，内部调试日志无需全面翻译。

## AI 语言

移除中文助手的固定身份约束，保留服务器上下文、工具协议、权限和命令执行限制。
普通聊天和确认操作在每次新请求开始时读取应用语言，加入默认回答语言指令；用户在任务中明确指定回答语言时优先遵循用户要求。
切换时不取消正在流式生成的回答，从下一次新请求生效；继续已有提议后的新模型请求也按该规则取值。
自动任务启动时捕获语言并绑定到任务上下文，后续轮次、暂停及恢复沿用该语言；下一次新任务使用新的设置。
UI 的自动任务状态按当前界面语言显示，与模型任务语言独立。
不为了切换语言重写既有消息、命令或服务器输出，不修改命令参数与 shell 语法。
无需新增独立 AI 语言设置。

## 布局

保留现有紧凑布局及 30px 栏高，使用短而清晰的英文翻译。
检查工具栏、模式和模型选择、状态栏、菜单、表单和弹窗；允许内容区域合理扩展，不能靠缩小字体或截断关键操作文字解决。
长说明可换行，必要的省略项提供完整工具提示。语言名称不使用国旗图标。

## 验收

1. 无配置、旧配置或无效配置均为英文；中英文选择持久化并在重启后恢复。
2. 保存失败不切换到未保存语言；快速切换不会发生偏好竞态。
3. 启动读取已保存中文时主界面不先显示英文；读取失败可重试。
4. 切换时 SSH 连接、终端内容、标签、草稿、运行任务和历史消息保留。
5. 页面、右键菜单、已打开弹窗、工具提示和无障碍标签即时更新。
6. 两种语言资源键、复数和占位参数一致；验证缺失翻译回退英文和未知错误保留原始详情。
7. 验证真实 Wails 错误信封解码，以及应用错误、执行结果和自动任务原因的翻译。
8. AI 普通请求按新语言，用户显式语言要求优先；运行中自动任务及恢复保持启动语言。
9. 英文和中文截图检查主窗口、设置、菜单、会话选择、命令确认和 AI 模式，验证紧凑布局。
10. 执行 Go 测试、前端测试与 TypeScript / Vite 构建；能够使用 Windows 环境时补充桌面烟测，否则明确报告其验证限制。

## 非目标

本轮不增加系统语言跟随、在线语言包、翻译管理平台、独立 AI 语言设置、历史内容机器翻译或额外语言的实际译文。
合并与发布由后续明确指令执行。
