# OpenShell 会话记忆设计

日期：2026-10-22
状态：设计与计划已获用户确认，功能分支实现及自动检查已完成；Windows 原生界面待实机验收，未合并或发布
基线：main / 7d638e48b3cd01db251231b250d82e9634f36545（v0.1.26）

## 目标

用户已同意增加历史对话持久化、按服务器隔离和长对话自动摘要，并确认“一个服务器拥有多条对话，多个 SSH 标签页共用该服务器的对话记录”。成功标准：关闭标签页或重启软件后能恢复对话；同一服务器的标签页能查看同一份对话列表、独立选择对话，并同步同一条对话的消息；不同服务器的消息不串线；长对话不再无限增长模型请求。历史记录与命令执行权限分开，恢复聊天不会恢复自动任务。

## 实现前代码事实

- internal/ai/context.go 的 ConversationStore 使用 map[tabID][]Message，只在内存保存。
- app.go 在 Connect 替换旧连接、CloseTab、ClearChat 时清空上下文。
- frontend/src/App.tsx 在连接时清空显示消息。
- internal/store/sqlite.go 没有聊天表；数据库已有 sessions、groups、profiles、hostkeys、preferences。
- internal/ai/provider.go 每次发送全部消息，请求 JSON 大于 2 MiB 时拒绝，未实现摘要。
- chatContext 为普通聊天、确认执行、自动模式的共用模型入口；finishTool 写入命令结果。

## 方案选择

采用现有 SQLite 保存历史；模型上下文使用“摘要 + 近期完整消息”。

替代方案：
- 仅保存历史、不摘要：实现较少，但无法解决长对话请求过大。
- 全量历史每次交给模型：最接近原始记录，但延迟、费用和上下文限制随使用增长。
- 向量检索：适合跨会话知识库；本次不引入额外依赖或检索服务。

## 连接与对话归属

隔离键包含已保存会话 ID、规范化 host、port、username，以哈希保存；同名不代表同服务器。host 仅去首尾空白、DNS 名称统一小写，不解析 DNS、不合并别名。修改显示名、文件夹不切断历史；修改 host、port、username 进入另一历史空间。不同已保存会话即使指向同一服务器也默认隔离。

服务器配置是历史记录的归属；标签页是 SSH 连接与操作入口，不拥有独占历史。每段对话有独立 conversationID，运行时 tabID 绑定当前选中的 conversationID 和 ConnectionRef.generation：

- 同一服务器的全部标签页读取同一份持久化对话列表；可新建、切换、重命名和删除对话。
- 普通打开或双击复制标签页：默认恢复该服务器最近使用的对话，即使其他标签页正在查看它；没有对话时才新建。复制标签页不会自动产生空白对话。
- 每个标签页独立选择当前对话；A 切换或新建对话不强制 B 跟随切换。新建后只在发起标签页选中，但所有同服务器标签页刷新列表。
- A、B 可以查看不同对话，也可以打开同一条对话。打开同一条时，用户消息、流式回复、命令结果和摘要状态实时同步，不重复追加。
- 每个服务器持久化 last_conversation_id，记录最近一次成功打开/切换/新建的对话；重启按此恢复。并发切换按后端提交顺序确定最后选择。
- 同一标签重连原服务器：保留当前选中的 conversationID、显示记录与摘要。关闭标签页只释放绑定，不删除对话。
- 实际连接目标变更：不把旧目标历史注入新连接。以 SSH manager 返回的实际 ConnectedSession 计算隔离键，不使用可能刚编辑的列表配置冒充当前连接。
- 连接失败或主机指纹未完成确认：不新建绑定，不改变已有历史；重试成功后才恢复。

## 共享对话与执行并发

每个 conversationID 有单独的运行所有权；不同对话仍受原有“每个 SSH 标签页只能运行一个任务”的约束。

- 发送消息、生成摘要、模型回复、等待命令确认、命令执行和自动模式连续步骤属于同一轮运行；所有权持续到完整结束或显式停止。
- 同一条对话只允许一个运行者。其他标签页可查看同步消息，但发送入口禁用，显示“正在另一标签页运行”；后端同样拒绝竞争请求，不能只依赖前端禁用。
- 一次运行固定 ownerTabID、ConnectionRef 和 conversationID；工具命令始终在发起运行的 SSH 连接执行，不随任何标签页切换而迁移。
- 只允许发起标签页确认/修改提案、继续或停止自动任务；其他标签页显示运行中的状态和发起标签页信息，并提供跳转入口。共享历史本身不授予执行权限。
- 发起标签页忙碌时禁止切换其当前对话；停止并完成清理后可切换。其他查看者可以自由切换。
- 发起标签页关闭、断线或连接 generation 改变时取消运行、废弃提案，保存已确认结果与中断状态，再释放所有权。其他标签页不会接管或自动重跑。
- 服务端事件携带 serverKey、conversationID、revision、eventID 和 ownerRef。历史类事件发给正在查看该对话的全部标签页；执行类事件只由 ownerRef 控制；以 eventID/消息 ID 去重，以 revision 拒绝过期数据。
- 流式消息更新固定消息 ID；加载历史时先订阅再获取带 revision 的快照，按版本合并缓冲事件，避免加载覆盖新消息。断线重连后从持久化快照校准显示。

本次不增加跨服务器共享记忆、自动恢复 SSH 登录或批量打开旧标签页。

## 数据结构与模块职责

数据库迁移在事务内增加以下表及索引，升级到 user_version=2，不覆盖现有数据：

1. conversations：id、server_key、session_id、title、summary、summary_through_seq、revision、created_at、updated_at。标题默认取首条用户消息的首行、最多 40 个 Unicode 字符；空对话显示当前语言的“新对话”，不把翻译文本固化为标题。用户可手动重命名。
2. conversation_messages：conversation_id、seq、id、role、content、tool_calls_json、tool_call_id、display_json、status、created_at；主键为 conversation_id + seq。
3. conversation_selections：server_key 主键、last_conversation_id，保存该服务器最近选择；不保存运行标签页或授权。
4. 索引 conversations(server_key, updated_at)；消息按 seq 稳定排序。对话列表按 updated_at 倒序、id 作为稳定次排序，每页 50 条。

display_json 只保存恢复 UI 所需的命令、结果、状态等数据，不序列化运行中的 Proposal/ConnectionRef。模型消息与显示记录来自同一后端事件，避免前端显示和实际上下文各存一份后失配。

- internal/store：迁移、事务追加、分页读取、原子清空、摘要版本检查；不依赖 ai 包。
- internal/ai：上下文预算、完整轮次切分、摘要提示词与摘要结果校验；不直接访问 SQLite。
- 会话服务：负责隔离键、共享对话列表、各标签页当前选择、每条对话运行所有权、消息提交、事件同步和摘要调度，放入独立文件，避免继续扩张 app.go。
- app.go/automatic.go：接入共用服务，保留现有连接 generation 校验和权限逻辑。
- 前端：按 conversationID 组织共享消息缓存，标签页只保存当前选中 ID 与自己的 SSH 状态；恢复和分页显示历史、同步其他查看者、展示摘要状态；同步 bridge、types 和 Wails 绑定。

持久化写入完成后才把消息标记为已保存。失败必须给出可见错误，不能静默退化为“已记住”。无需向用户展示数据库字段或隔离键。

## 消息完整性与执行恢复

- 用户消息在模型请求前保存一次，使用稳定消息 ID 避免重试重复写入。
- 成功回复在 SSE 结束后提交；被停止、断线或异常中断的回复保留已接收文本并标记 incomplete，不能作为完整 assistant/tool 消息重放。
- assistant.tool_calls 与对应 tool 结果必须形成有效序列。执行前先保存 tool_call，真实执行后立即写结果；确认拒绝也保存明确的未执行结果。
- 恢复时发现无结果 tool_call：显示“结果未知/未完成”，不自动执行、不推断成功；提供本地生成的配对 tool 消息说明缺失结果，不把未知状态当作失败后自动重试。
- 重启、重连不恢复旧提案确认按钮、自动任务、临时 cwd、shell 环境或执行授权。再次执行必须基于当前连接重新提案。
- 历史摘要作为不可信历史资料注入，不使用 system 角色承载摘要内容，不能覆盖当前权限与目标系统提示词。
- 当前系统提示词每次重新生成，使用当前服务器、语言、模式；更换模型不清空对话。

## 自动摘要与请求预算

第一版不假设自定义 API 提供准确的模型上下文元数据，采用保守的 UTF-8 字节预算，并在 UI 明示这不是精确 Token 数：

- 请求上下文默认预算 48 KiB，含系统提示词、摘要、消息、工具定义和 JSON 编码开销；最终以序列化请求大小校验。
- 完整轮次超过 20 轮或下一次请求预计超过预算时，在同一请求生命周期内压缩最旧的完整轮次。
- 尽量保留最近 6 个完整轮次；预算不足时可减少，但保留当前用户消息和完整工具调用链，不能只保留孤立 tool 消息。
- 摘要目标不超过 8 KiB；输入按完整轮次分批，每批含旧摘要与待压缩消息并控制在 32 KiB。
- 摘要使用当前已选择 API/模型，禁用工具，超时 30 秒，沿用该请求冻结的语言、profile、key。摘要请求不进入聊天记录，也不占用自动执行命令上限。
- 提示词要求保留用户目标、服务器事实、关键路径/端口、已确认操作与真实结果、待办和未知项；明确区分历史事实与当前状态。
- 输出为空、超限或调用失败：不覆盖已有摘要与进度；完整历史不删除。此次使用最近完整轮次构造有界上下文，并显示“本次使用近期记录，摘要未更新”，后续正常请求再尝试。
- 如果当前消息或不可拆分工具链单独超过预算，明确提示缩短输入或附件；不静默截断用户消息、不发送超大请求。
- 摘要请求取消时中止当前聊天；不在用户已停止后继续发出主回复请求。
- 摘要提交采用 revision/summary_through_seq 检查，清空或连接变更后旧摘要不能回写复活数据。

摘要会额外使用模型额度，默认开启且仅在达到阈值时触发。设置增加“保存聊天记录”“自动摘要”，默认均开启；关闭保存前需停止所有正在运行的聊天和自动任务；随后为各服务器创建内存临时对话集合，同服务器标签页继续共用临时列表，旧记录保留但不加载、不更新。重新开启前同样需停止任务，结束临时对话并按正常恢复规则加载持久化历史；不自动将临时内容落盘。关闭自动摘要只使用有界近期上下文，给出相应状态，不恢复无限请求。

## 清空、删除与隐私

- “清空对话”删除当前 conversationID 的原始消息和摘要，保留空对话与手动标题；删除的是共享记录，因此所有查看该对话的标签页同步变空。确认弹窗明确影响范围，不影响该服务器的其他对话。
- “删除对话”删除该对话及全部消息和摘要；先确认且不能删除运行中的对话。所有正在查看它的标签页同步选择该服务器最近更新的其他对话；没有其他对话时原子新建一个空对话供这些标签页共同选择。同步修正 last_conversation_id。
- 进行中的聊天、摘要或自动任务需先由发起标签页停止；清空/删除与提交通过 conversationID 锁和 revision 串行化。删除后的迟到事件不能重建消息或恢复选择。
- 删除保存的 SSH 会话时，事务删除其全部历史；保留现有“先关闭相关标签页”的约束。
- 终端输出仍只在用户明确附加或 AI 实际工具执行后进入历史，不新增整屏自动上传。
- 写入前复用 Redact，覆盖文本、命令参数和结果的常见密码、Token、私钥；该规则不是全量秘密检测。
- 不保存 API Key、SSH 密码、私钥内容或临时凭据。聊天历史使用本地数据库，第一版不承诺额外的数据库加密。
- 本次不自动按天删除历史；列表分页每次读取 100 条，摘要不删除原始记录，避免长历史一次性加载到界面。删除会话/清空负责显式回收。

## 界面行为

保持现有 AI 侧栏布局，在聊天工具栏提供紧凑的当前对话选择器和“新建对话”按钮；下拉列表显示该服务器所有对话的标题和更新时间，提供重命名/删除入口。选择器支持分页加载，对话切换不切换 SSH 标签页。

增加轻量状态文字：已恢复历史、正在整理上下文、已使用摘要/近期记录、正在另一标签页运行。英文默认与中文翻译同步提供。

恢复接口返回 conversationID、消息分页、摘要状态，不返回可执行提案。连接成功后加载最新 100 条，可点击“加载更早记录”。加载中禁止发送；失败允许重试，不能以空白新对话悄悄覆盖原记录。历史消息按 serverKey、conversationID、revision 同步给全部查看者；命令确认和执行操作额外校验 ownerTabID 与连接 generation。不能因为观看标签页与发起标签页 generation 不同而丢弃共享消息。

## 接口边界

- Connect 的成功结果增加 conversationID 及恢复状态，不在指纹 challenge 阶段绑定对话。
- ListConversations(ref, cursor, limit) 读取当前服务器的共享对话列表。
- CreateConversation(ref)、SelectConversation(ref, conversationID)、RenameConversation(ref, conversationID, title)、DeleteConversation(ref, conversationID) 管理同服务器对话；均由后端验证归属。
- ReadConversation(ref, conversationID, beforeSeq, limit) 返回一页安全的显示消息、摘要状态、revision 和运行所有者；允许同服务器不同标签页查看同一对话。
- Chat/Continue/自动任务使用标签当前绑定的 conversationID，不接受任意跨目标历史 ID。
- 复制标签和普通打开使用同一服务器最近选择；同标签重连优先保留原选择；显式新建对话才创建新的 conversationID，不依赖标签名称判断。
- ClearChat 保留现有入口，内部定位 conversationID 并原子清空共享消息与摘要，向全部查看者广播变更。
- 历史接口和事件变更同步更新生成的 Wails 声明、前端测试替身与 e2e 后端替身。

## 验证与验收

实现阶段先写失败测试，再实现并运行完整项目检查：

1. 数据库从 v1 迁移、重复打开、关闭后重新打开能恢复原消息与摘要，原有 sessions/profiles/preferences 保留。
2. 不同服务器、相同地址不同用户、不同保存会话不串记录；同服务器所有标签页列表一致，可同时打开一条对话并同步消息，也可各自选择不同对话。
3a. 复制标签恢复该服务器最近选择，不自动新建；新建只改变发起标签页的当前选择，但所有同服务器标签页能看到新记录。
3b. 同一对话同时发送只有一个请求获得运行所有权；不同对话遵守每标签单任务限制。等待确认和自动任务轮次之间不提前释放所有权。
3c. 命令只在发起标签页的连接执行；旁观标签页不能确认或接管；关闭/断开发起标签停止运行，其余查看者能看到中断状态。
3. 重连保留历史；修改目标隔离；改名不丢历史；连接失败/指纹 challenge 不覆盖历史。
4. app 重建后恢复已保存对话；未完成 tool_call 正确配对但不执行，自动任务与权限不恢复。
5. 清空/删除后完整删除摘要及消息，所有查看者同步；其他对话保留，删除当前对话后回退选择正确；并发迟到的 SSE、执行结果、摘要不能复活记录。
5a. 同时加载历史与接收流式事件不丢消息、不重复追加；发起标签页和旁观标签页的不同 generation 不妨碍共享历史同步。
6. 超阈值触发摘要，最近轮次保留，完整工具链不被拆开；序列化请求在预算内。
7. 摘要失败、输出超限、超时、取消、超大单条输入都有明确行为，原始历史与已提交摘要不丢失。
8. 中英文恢复、加载更早、状态提示及设置行为；保存关闭后不加载或更新持久化历史。
9. 数据库写入失败可见；前端加载竞态不覆盖另一个标签；落盘内容经过脱敏。
10. 执行 go test ./...、适用的 Go race 测试、npm test -- --run、npm run build，以及聊天恢复的 Playwright 测试；检查 Wails 绑定一致性。
