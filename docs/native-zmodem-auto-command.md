# 原生 ZMODEM：单文件 rz/sz 交互

> OpenShell Windows 版使用 Go + Rust 原生 ZMODEM 引擎；每次命令只允许传输一个文件。批量文件和目录操作请使用 SFTP 文件面板。

## 用户操作

| 终端命令 | 结果 |
| --- | --- |
| `rz`、`rz -q` | 在本地选择 **一个普通文件**，上传到当前 SSH Shell 目录 |
| `sz report.bin` | 选择本地保存目录，下载当前 Shell 目录下的单个远端文件 |
| `sz -- '/tmp/中文 文件.bin'` | 支持安全的字面量引号和中文路径 |
| `sz file1.bin file2.bin` | **拒绝**，在远端启动协议前清理命令输入并提示使用 SFTP |
| `rz -y`、Shell 管道、通配符和复合命令 | 不进入原生自动接管；保留 Shell 原始行为 |

单次只能处理一个普通文件。目录上传、批量上传、批量下载、并发传输由 SFTP 负责；ZMODEM 不自动覆盖同名文件、不做断点续传。单文件仍受原生 sidecar 的小于 2 GiB 兼容性上限约束。

## 接管边界

1. 仅在普通 POSIX Shell 提示符，且用户直接输入未编辑的 `rz` / `sz` 字面量命令时执行自动接管。JumpServer、交互式 REPL 或 AI 占用终端时不自动接管。
2. 自动接管把用户输入行的 Enter 替换为 Ctrl-U，远端不执行裸 `rz/sz` 命令。选择器取消不会启动传输。
3. Windows 原生传输由单文件入口 `StartNativeZmodemInteractiveTransfer` 启动。为旧版前端保留的 `StartNativeZmodemInteractiveBatchTransfer` 也在 **Go 后端** 拒绝多个路径，不能依赖前端单选作为唯一防线。
4. 传输时协调器独占当前 SSH PTY 的输入和输出，阻止键盘、粘贴、终端 AI 与 ZMODEM 二进制协议相互干扰。
5. sidecar 文件字节数达到总大小只是数据阶段完成。必须等待 sidecar 正常退出、远端带令牌的结束边界及 Shell 恢复成功后，才允许 UI 报告完成；下载此后再发布临时文件。
6. 取消、失联、协议异常或远端结束状态不明时必须 fail closed，避免将剩余协议字节输出到终端或未经验证恢复输入。此时需要重新连接终端。

## 回归验证

- 空文件、Unicode 文件名、二进制文件、跨大小文件的双向 SHA-256 一致性
- 单文件上传/下载、记忆目录、取消选择器、连续执行多轮传输
- 多文件 `sz` 明确拒绝、旧批量 API 拒绝、单选器只允许一个文件
- 传输期间键盘/粘贴/AI 被阻止，取消和 SSH 中断后无协议数据泄漏
- 弱网/丢包/传输超时，只有远端确认完成后才显示 100%

## 历史兼容

已有批量模式的协议层实验辅助函数及测试暂时保留，供回归参考。它们不再由 OpenShell 的正式单文件入口触达，旧版批量选择和跳过功能已停用。在独立 CI 对单文件全链路回归通过前，不删除经过验证的 Rust/Go 协议核心。
