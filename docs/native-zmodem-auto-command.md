# 原生 ZMODEM：单文件 rz/sz 交互

> OpenShell Windows 版使用 Go + Rust 原生 ZMODEM 引擎；每次命令只允许传输一个文件。批量文件和目录操作请使用 SFTP 文件面板。

## 用户操作

| 终端命令 | 结果 |
| --- | --- |
| `rz`、`rz -q` | 在本地选择 **一个普通文件**，上传到当前 SSH Shell 目录 | 
| `rz -y`、`rz --overwrite`、`rz -q -y` | 原生单文件覆盖上传；选择文件后必须明确勾选确认，远端执行 `rz -q -y` |
| `sz report.bin` | 选择本地保存目录，下载当前 Shell 目录下的单个远端文件 |
| `sz -- '/tmp/中文 文件.bin'` | 支持安全的字面量引号和中文路径 |
| `sz file1.bin file2.bin` | **拒绝**，在远端启动协议前清理命令输入并提示使用 SFTP |
| `rz`、`sz file` 输入中退格纠错 / 行首空格 / Ctrl-U 清行 | 在已验证普通 Shell 提示符下按修改后的字面量命令处理；不支持 Shell 历史记录或光标移动推断 |
| 粘贴 `rz\nwhoami\n` 等包含传输命令的多行内容 | **整段拦截**并提示分开执行，避免远端提前启动未经接管的协议 |
| `trz`、`tsz` 和未列出的特殊 `rz` 参数 | 不支持，能识别时明确拒绝；请使用 SFTP |
| Shell 管道、通配符、复合命令或不可信的提示符 | 不自动接管；如果出现未经授权的 ZMODEM 帧，终端输出被隔离并提示重连 |

单次只能处理一个普通文件。目录上传、批量上传、批量下载、并发传输由 SFTP 负责；普通 `rz` 不强制覆盖；只有明确执行 `rz -y`/`rz --overwrite` 并在选择器中确认后，才允许覆盖远端同名文件。取消或失败时远端文件可能不完整，不能保证原内容可恢复。不支持断点续传。单文件仍受原生 sidecar 的小于 2 GiB 兼容性上限约束。

## 接管边界

1. 仅在普通 POSIX Shell 提示符、已验证提示符的当前输入行可被安全跟踪，且输入 `rz` / `sz` 字面量命令时进行客户端命令接管。支持行尾退格、行首空格及 Ctrl-U 清行；不猜测历史记录、Tab 补全及光标移动后的远端编辑结果。JumpServer、交互式 REPL 或 AI 占用终端时不自动接管。
2. 自动接管把用户输入行的 Enter 替换为 Ctrl-U，远端不执行裸 `rz/sz` 命令。输入行被接受后，Go SSH 管理器在整个选文件期间保留终端输入权，禁止手动输入和终端 AI；用户取消选择时必须匹配 SSH 连接代际和本次 selectionId 才解除保留，用户确认传输时原子移交给 Rust ZMODEM 任务，同时发送输入解锁事件给前端；乱序或过期的选择器事件不能重新锁定终端。取消时同时恢复先前已验证的普通 Shell 就绪状态，让用户不必额外按 Enter 就能再次使用 rz/rz -y/sz；交互式 REPL、JumpServer、全屏程序及状态不确定的终端不执行此恢复。选择器取消不会启动传输。多行粘贴中只要出现传输命令，整段被拒绝，避免执行未接管的远端 `rz/sz`。
3. Windows 原生传输只通过 `StartNativeZmodemInteractiveTransfer` 启动，并由 Go 后端和远端命令生成器共同校验方向、本地路径与唯一远端文件。已移除旧批次兼容入口，不能仅依赖前端单选。
4. 传输时协调器独占当前 SSH PTY 的输入和输出，阻止键盘、粘贴、终端 AI 与 ZMODEM 二进制协议相互干扰。旧兼容过滤器已删除，终端传输期间依然由 Go/PT Y 独占机制屏蔽键盘与 Ctrl+C；未经接管的协议数据不会回退。
5. sidecar 文件字节数达到总大小只是数据阶段完成。必须等待 sidecar 正常退出、远端带令牌的结束边界及 Shell 恢复成功后，才允许 UI 报告完成；下载此后再发布临时文件。
6. 只能从传输中心的取消按钮发起取消：原生链路使用协议 CAN 序列，不允许普通终端 Ctrl+C 输入。取消、失联、协议异常或远端结束状态不明时必须 fail closed，避免将剩余协议字节输出到终端或未经验证恢复输入。此时需要重新连接终端。

## 原生协议启动帧校验

原生 ZMODEM 扫描器在接管终端输出前，会按 `ZHEX` 格式识别 `ZRQINIT(0)` / `ZRINIT(1)`，解码帧类型、四字节参数及 CRC-16，并按 CRC-16/XMODEM（多项式 `0x1021`）验证。错误 CRC、错误类型和未完成帧不能启动已授权的原生传输接管。对于未经 OpenShell 授权的疑似 ZMODEM 帧，即使 CRC 错误，仍保守隔离，防止可能的二进制协议数据进入终端。帧可能跨多个 SSH stdout 数据块，识别器保留最多 17 字节候选前缀，并继续检查同一批输出中的后续有效帧。

CRC 是校验和，不是身份验证。只有已获授权的原生接管才要求 CRC 有效，避免将错误启动头传给 Rust sidecar；未由 OpenShell 接管的远端输出，即使只是疑似或已损坏的 ZMODEM 头部，也仍采取 fail-closed 隔离，避免未经验证的协议字节进入 xterm。真正的远端启动自动接管还需要可靠的终端所有权切换、文件选择和远端结束证明。

参考：https://sources.debian.org/src/lrzsz/0.12.21rc-0.2/src/zm.c/ （`zshhdr` 的 CRC 计算）。

## 回归验证

- 空文件、Unicode 文件名、二进制文件、跨大小文件的双向 SHA-256 一致性
- 单文件上传/下载、记忆目录、取消选择器后继续键入命令、连续执行多轮传输
- 行首空格、行尾退格、Ctrl-U、单行 LF/CRLF、中文文件名编辑，混合多行粘贴不得启动远端协议
- 文件选择器保持打开时，手动输入和终端 AI 都被阻止；旧连接代际的取消消息不能解除新会话的预留
- `rz -y`/`rz --overwrite` 确认勾选、远端已有文件覆盖、普通 `rz` 不改变模式、取消或传输失败不得误报成功
- 多文件 `sz` 明确拒绝、旧批量接口不再导出、单选器只允许一个文件
- 原生传输及文件选择期间键盘/粘贴/AI 被阻止，用户 Ctrl+C 被拒绝；仅传输中心取消生效，取消和 SSH 中断后无协议数据泄漏
- 弱网/丢包/传输超时，只有远端确认完成后才显示 100%

## 历史兼容

Windows 本地 ZMODEM 仅使用 Go + Rust sidecar。`trzsz-go` 及旧版兼容过滤器、批次传输与 UI 已移除；Rust sidecar 的低层压力测试保留，用于协议互操作与故障注入。`cmd/zmodem-launcher` 是发行包中指向 Rust sidecar 的**原生启动辅助程序**，并非旧协议兼容引擎。
