# 原生 ZMODEM：Windows GUI 集成验收（开发者实验）

> **范围**：此清单只验收显式 opt-in 的“原生 ZMODEM · 实验模式”按钮及现有交互式 SSH PTY 传输。它不代表在终端里直接输入 `rz/sz` 后自动切换为原生实现；目前该场景仍由旧的 trzsz-go/lrzsz 路径处理。测试不应在生产 SSH 会话执行。

## 前置条件

1. Windows 11/Windows 10 x64；使用源码开发构建或确认内含 `zmodem/native/zmodem-sidecar.exe` 的测试包。
2. 独立 Linux OpenSSH 测试机（建议 Docker SSH Lab），已安装 `lrzsz`；服务器使用普通 POSIX Shell，非 JumpServer、非 tmux/screen。
3. 通过 `scripts/test-native-zmodem.ps1` / netem 测试确认原生 sidecar 的协议完整性回归成功。记录测试命令、提交 SHA、摘要及日志路径。
4. 启动应用前通过 PowerShell 显式设置 `$env:OPENSHELL_NATIVE_ZMODEM_EXPERIMENT = "1"`。开发构建若 sidecar 不在默认路径，另设置 `$env:OPENSHELL_NATIVE_ZMODEM_SIDECAR` 为可执行文件的**绝对路径**。
5. 测试文件至少包含 0 B、16 KiB、1 MiB、包含中文和空格文件名的二进制文件；另准备不同随机内容的重名文件。使用 `Get-FileHash -Algorithm SHA256` 与远端 `sha256sum` 比较。

## Windows GUI 实机验收矩阵

| 编号 | 手动操作 | 必须观察到的结果 |
| --- | --- | --- |
| G01 | 不设置实验变量启动 OpenShell，在 SSH 工具栏查找原生入口 | 不出现实验入口，现有 `rz/sz` 路径不变 |
| G02 | 设置实验变量后连接实验 SSH，打开实验弹窗 | 显示当前会话、风险提示、上传/下载方向；未选择路径及勾选确认时不可开始 |
| G03 | 点击上传，选本地文件，勾选确认后开始 | 使用**当前交互式 Shell 的工作目录**接收；进度可见且完成后 SSH 提示符正常，上传文件 SHA-256 相符 |
| G04 | 点击下载，填写绝对远端路径、选本地目录、勾选确认后开始 | 下载只在成功后发布，文件 SHA-256 相符；已有同名文件不得静默覆盖 |
| G05 | 对 0 B、16 KiB、1 MiB、中文及空格文件名重复 G03/G04 | 无乱码、残留二进制协议帧、文件截断；空文件或不支持的文件应明确提示失败而非假成功 |
| G06 | 上传/下载期间观察进度和关闭按钮 | 处理中进度不得显示 100% 成功；运行期间不能误关闭进度弹窗；只在远端完成确认后显示成功 |
| G07 | 正在传输时点击取消 | 结束或返回明确错误，不能显示成功；若未能确认远端 Shell 状态，原标签不可再复用，要求重连 |
| G08 | 传输中断开 SSH、关闭标签或中断网络 | 传输取消且终端不再接受不安全输入；不得将半成品发布到下载目标目录 |
| G09 | 模拟 sidecar 失败/超时，直接尝试再次传输或 AI 执行 | 被拒绝并提示先重新连接；刷新“终端就绪”状态之前不能短暂允许重复提交 |
| G10 | 异常之后新建或重连 SSH，再操作 | 新代际连接恢复可用；旧传输的取消、进度或回调不影响新连接 |
| G11 | 同时打开两个 SSH 标签，A 传输时在 B 正常敲命令/传输 | A/B 的字节流、传输进度、取消及文件互不串扰 |
| G12 | 在同一标签连续完成上传→下载→上传 | 不遗留 PTY 独占状态、不弹出旧文件选择器，终端正常工作 |
| G13 | 在 JumpServer 会话或终端正被 AI/传统 ZMODEM 占用时尝试启动 | 明确拒绝且不损伤正在工作的任务 |
| G14 | 禁用实验后，再在远端 Shell 手动执行 `rz/sz` | 正式旧路径仍正常；不能因为实验代码改变或泄漏原生协议字节 |

## 自动化覆盖与实机边界

- **Go 单元/生命周期**：`go test -race ./internal/ssh`（连接代际、取消/断开、同标签互斥、PTY 独占、失败后 fail-closed）。
- **React 弹窗回归**：`cd frontend; npm test -- --run NativeZmodemExperimentDialog`（选文件、确认、进度、取消、失败后重试门禁、会话隔离）。
- **全项目 CI**：`cd frontend; npm run build; npm test -- --run` 以及 `go test -race ./...`。
- **必须人工证明**：G01–G14 的真实 Windows OpenShell 桌面窗口与独立 Linux OpenSSH 往返，不能以 Vitest mock、Docker 内测试或“CI 绿灯”代替。出于运行环境限制，自动化不证明 Win32 文件选择器、WebView2 焦点或真实 GUI 可用。

## 留存证据与通过门槛

每个 G 项记录：测试时间、Windows/Go/Rust/OpenShell 版本、测试提交 SHA、Linux 系统版本、会话代际、测试文件大小、SHA-256 双端摘要、结果（PASS/FAIL/BLOCKED）、截图或日志路径。中断类测试需保留取消/断线后的终端状态与本地目标目录内容。

**准入要求**：所有 G01–G14 都有可追溯的 PASS 或经确认不适用的记录；关键项 G03、G04、G07、G08、G09、G10、G11、G14 不能豁免。任一协议字节泄漏至终端历史/AI、同名覆盖、半成品发布、跨会话取消、取消后错误恢复，均阻止默认启用及正式发布。

## 暂不启用自动接管

直接把远端输出中的 ZMODEM 启动帧当作自动执行授权存在协议注入风险；普通 `cat`、恶意输出也可能包含相同帧头。后续自动识别方案必须同时具备用户命令意图绑定、方向和 CRC 检查、会话代际校验、明确的文件选择授权、远端完成证明以及 fail-closed 恢复。**本阶段不修改旧 `rz/sz` 检测链路，也不改变默认引擎。**
