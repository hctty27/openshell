# 原生 ZMODEM：Windows GUI 集成验收

## 范围和基线

Windows 正式包只使用 Go + Rust 原生单文件 ZMODEM；不再提供旧 trzsz-go、trz/tsz、兼容引擎切换或开发者实验按钮。原生 sidecar 可用时默认支持字面量命令和远端主动握手；交互式 Bash 的结束标记恢复也默认启用。

本清单适用于安装版和完整解压后的便携版。**以下均为待执行的实机用例，不是已经通过的测试结果。** 基线 v1.0.35 的被动选择器取消仍可能要求重连；涉及 D1 的预期仅适用于包含 #317 的候选构建。其他安全专项同理，以待验收构建实际包含的提交为准。

## 前置条件

- Windows 10/11 x64，记录 OS、WebView2、版本及 Git SHA；确认安装包/便携包内有 Rust sidecar 和第一方启动器。
- 隔离 Linux OpenSSH 测试机，安装 lrzsz；先用 Bash 测试，再用非 Bash 或嵌套 Shell 测试隔离边界。不在生产会话进行故障注入。
- 准备 0 B、16 KiB、1 MiB、16 MiB、1 GiB、中文/空格文件名及不同内容的重名文件。在两端使用 SHA-256 比较。单文件遵守当前原生大小限制。
- 正式包不需要设置历史实验环境变量。开发环境可用 OPENSHELL_NATIVE_ZMODEM_SIDECAR 指定 sidecar 路径。

## 手工验收矩阵

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| G01 | 安装版、便携版分别启动；检查设置和终端菜单 | 无旧兼容引擎设置或实验按钮；不要求配置已移除的实验开关 |
| G02 | Bash 下直接执行 rz 和 sz file | 弹出正确方向的单文件选择器；选择阶段不允许键盘、粘贴或终端 AI |
| G03 | 执行 rz 上传 | 当前远端目录收到文件，SHA-256 一致；任务完成状态正确 |
| G04 | 执行 sz 下载 | 选定目录收到完整文件；同名本地文件不得静默覆盖 |
| G05 | 空文件、二进制、中文空格路径、大文件 | 文件名正确、摘要一致、无残缺下载或二进制终端输出 |
| G06 | 执行 rz -y 和普通 rz，准备已有同名文件 | 覆盖模式明确确认，普通模式不强制覆盖；拒收有通知及失败记录 |
| G07 | 用历史命令、bash -c、复合命令启动远端 rz/sz | 识别有效握手，出现匹配的选择器，不重复执行远端命令 |
| G08 | 直接命令选择器取消，再执行 pwd，重新传输 | 未启动的远端命令不被发送；原终端可立即使用 |
| G09 | 被动 rz/sz 选择器取消（包含 #317） | 已验证 Bash 退出时恢复同一终端；下一条命令执行成功且可再次传输 |
| G10 | 被动 sz 请求不存在的文件（包含 #317） | 约 15 秒报告失败；有有效 Bash 退出标记时恢复同一终端；不发布残缺文件 |
| G11 | 传输中取消、sidecar 失败、超时 | 不误报成功；经过验证才能恢复；未验证时保持输入锁并显示重连按钮 |
| G12 | 非 Bash、嵌套 Shell 或没有可靠结束证明 | 不使用普通提示符/延时解锁；终端内提示重连，不主动切换本地终端 |
| G13 | 传输中断网、关标签、重连 | 旧代际任务、取消、进度及回调不影响新连接 |
| G14 | 双标签同时传输或一个传输另一个输入 | 进度、文件、输入和取消互不串扰 |
| G15 | 同标签连续上传、下载、上传 | 无残留输入锁、旧选择器或历史二进制数据 |
| G16 | 多文件 sz、旧 trz/tsz、JumpServer/REPL/AI 占用 | 不冒充支持；未获授权的握手安全隔离，建议使用 SFTP |
| G17 | 传输阶段尝试键盘、粘贴、Ctrl+C、关闭面板 | 终端不接受普通输入；通过传输中心的取消操作结束任务 |

取消或失败的覆盖上传可能损坏远端旧文件；ZMODEM 不是事务性替换。失败后的恢复不等于传输成功。

## 自动化与实机证据

- Go race: go test -race ./...；前端: npm run build 和 npm test -- --run（在 frontend 目录）。
- GitHub Actions 的 Windows terminal smoke 与 Windows native ZMODEM feasibility 验证编译、Rust 互操作等自动化场景。
- #317 的 Linux OpenSSH/lrzsz 日志可作为自动化基线（[运行记录](https://github.com/hctty27/openshell/actions/runs/45306056647)），不能作为 Windows 桌面操作通过的证明。

每项记录构建 SHA、包类型、时间、服务器/Shell、操作步骤、预期、实际结果、PASS/FAIL/BLOCKED、日志或截图；文件测试记录双端 SHA-256。

发布门禁：所有适用的关键用例通过；未测项明确标记。出现错误恢复、跨标签输入、协议字节泄漏、静默覆盖或残缺下载时阻止发布。另见 [综合稳定性验收](stability-acceptance.md)。
